# Provider conversations and prompt caching

Verified against the source and local test runs on 2026-10-24. Installed releases must include these changes before inheriting this behavior.

## Design and boundaries

Headless describes how a CLI is controlled, not whether it forgets the conversation. Main and worker sessions are separate. Compatible Main conversations keep native IDs and an acknowledged context snapshot; follow-ups send new messages and changed metadata. The saved continuation is kept in the existing session journal, excluded from renderer snapshots. Model/policy/schema changes and edited or cleared history rebuild context. Uncertain failures invalidate continuation instead of automatically replaying a potentially accepted request. A confirmed missing Codex thread may be replaced before sending the full context.

Main Codex threads are durable and resume with the same read-only, no-tools configuration. Claude Main uses persistent `--resume` sessions while keeping tools/MCP disabled. Cursor uses ACP `session/load`; its response schema remains locally validated without appending another copy of it to each resumed prompt. DeepSeek Main keeps a separate read-only host, so even versions without durable ACP resume can continue while Harness remains open. After restart, native durable-resume support is still required. Muse and Antigravity take Main and routing calls too since 2026-10-31. They resume their own sessions and skip the schema on a resumed prompt like the others, but their kept-conversation resume is untested.

Workers save instruction fingerprints alongside their native session IDs. Cursor/Muse/Antigravity/DeepSeek do not append unchanged instructions again as user messages. Rules/access/workspace changes refresh them. Claude and API workers continue supplying the same stable system prefix, as their protocols require. Codex reloads inject changed instructions or refresh after observed compaction, once the active turn has settled; a legacy session without a fingerprint gets one refresh. This is not a guarantee that a provider's lossy automatic compaction will preserve every old instruction verbatim; large-context CLI compaction was not live-tested in this audit.

Group history is conversation data, not changing developer instructions. Each member gets messages since its last completed group reply. Failed work does not advance that cursor. The context is stored with the user turn so switching providers can reconstruct it. Other groups and private Main chat stay separate. Normal project instruction reads/checks are local file operations, not extra model calls.

Source: `src/routing/smart-router.cjs`, `src/controller.cjs`, `src/controller/coordinator.cjs`, `src/group-chats.cjs`, `src/providers/{claude,cursor,deepseek,api-agent,providers,prompt-cache}.cjs`.

## API rules

API workers and Main keep an ordered message prefix, including provider reasoning/tool messages. Chat Completions still sends history over the wire; server caching may avoid recomputing it. OpenAI gets a stable `prompt_cache_key`, xAI a stable conversation header, and OpenRouter a stable session identifier. OpenRouter Anthropic uses automatic cache control; documented Alibaba endpoints use bounded explicit breakpoints. Unsupported snapshot models and arbitrary compatible endpoints receive no invented options. DeepSeek and supported local servers use their native automatic prefix caching. Independent API structured calls use an affinity key derived from their stable policy/schema, without sharing conversation history.

Provider-reported missing cache counters remain unknown. Cache writes are separate from reads. Tool loops with missing usage reports are marked incomplete; reported totals are lower bounds. Format-repair attempts remain counted. Cache misses/eviction and cache-write pricing mean no guaranteed saving can be inferred from session reuse alone.

## Follow-up review corrections, 2026-10-24

Group context filters commentary before applying the 40-message/48,000-character bound. A 45-progress-message fixture retains the original request and final answer. The per-turn block contains only new group messages and is empty when there are none; the shared behavioral preamble remains in stable worker instructions. Source: `src/group-chats.cjs`; regression: `tests/prompt-cache.test.cjs`, UI round trip: `tests/group-chat-ui-check.cjs`.

JSON format repair appends a note to the current prompt, leaving the original policy fingerprint intact. A native CLI whose turn completed keeps its session for the repair, so the retry sends only the note, not the accepted request again. This includes DeepSeek, which rejects invalid JSON inside `run()` and now keeps its private Main host for that case. API repair keeps the saved prefix because the invalid reply is never stored. Codex repairs within its existing thread. A deleted Claude Main transcript (`No conversation found with session ID`, reported by Claude Code 2.1.309 with zero turns and zero cost) restarts once with the full context. Missing-thread recovery initializes inference timing through the same turn-start function as normal calls, so setup/fallback measurements remain finite. Source: `src/routing/smart-router.cjs`; regression: repair sequences and missing-thread timing in `tests/prompt-cache.test.cjs`.

Missing/corrupt API history recovers automatically only before inference and only when the owning controller supplies its complete available Harness transcript. Filesystem permission errors and uncertain provider failures are not automatically replayed. Current instructions and group context remain included. Source: `src/providers/api-agent.cjs`, `src/controller.cjs`; regressions: missing/corrupt fixtures in `tests/api-agent.test.cjs` and real Controller/ApiAgent integration in `tests/core.test.cjs`.

Manual Codex compaction clears the instruction fingerprint and loaded-thread marker after its turn completes. Observed automatic compaction clears only the fingerprint: the native thread remains loaded while its current turn continues. `Controller.resume` refuses reload while a submission is pending or active, including after a settings change invalidates the loaded marker. At the next safe resume, the missing fingerprint triggers one instruction refresh; subsequent unchanged turns reuse it. This does not establish what the provider retains during inference inside a long automatically compacted turn. Source: `src/controller.cjs`, `src/controller/turns.cjs`; regressions: owned manual/automatic compaction and chat reopening in `tests/core.test.cjs`.

Native Main transcripts use a 30-day unused-record retention policy, checked once per day of provider use. Only the dedicated router workspace is eligible; active Harness references are protected even when old. Codex uses `thread/list` with exact cwd/app-server filters and `thread/delete`, preserving running, unknown-age and section-filed threads. Codex 0.163.0 and the Harness-selected 0.164.0-alpha.11.1 have no pin field (their `Thread` schema has `section` instead), so absence of `isPinned` does not defer cleanup; a future `isPinned: true` is still preserved. Claude checks its encoded workspace bucket plus transcript session ID/cwd in bounded head/tail reads; symlinks, corrupt ownership records, unexpected nested transcripts and unrelated workspaces are preserved. Unsupported or failed cleanup logs a deferred-cleanup warning and retries on a later day. It never deletes Harness's own chat history or changes personal retention settings. Source: `src/providers/conversation-retention.cjs`; regressions: pagination, live references, wrong workspace, pinned/running threads, Claude ownership and large transcripts in `tests/prompt-cache.test.cjs`.

Native deletion was checked with a newly created disposable Codex thread on installed `0.164.0-alpha.11.1`; deletion passed with zero inference calls (`.scratch/cache-retention-metadata-final.log`). The first test helper hit Windows EBUSY while removing its empty working folder before process exit; awaiting process exit fixed the helper and the folder was removed. Claude retention uses synthetic store fixtures, not a signed-in live model. References: [Codex lifecycle API](https://learn.chatgpt.com/docs/app-server), [Claude native session store](https://platform.claude.com/cookbook/claude-agent-sdk-05-building-a-session-browser), and [official session lookup implementation](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/sessions.py).
