# Local agents

Verified against live source: 2026-10-09.

`src/agents.cjs` coordinates the existing `Controller` instances. Main retains `sessions.json`; each named agent uses `agents/<uuid>/sessions.json` under the same application data directory. The primary store holds agent profiles. Each controller owns its provider processes, routing state, approvals, tool bridge, turn queue and cleanup state. `src/main.cjs` creates separate API proxy instances too: the proxy's model effort map must not be shared across concurrent agents.

`Agents.saveAgent` persists and returns the profile without awaiting `initializeController`. Startup runs in the background with errors retained in the controller snapshot. `Controller.initialize(shared)` reuses the primary Claude/Cursor status and models after primary discovery completes instead of repeating their auth/model-discovery subprocesses; each agent still connects its own Codex app-server. Closing guards prevent a pending configuration or bridge startup from launching another worker after shutdown begins. Shared provider refresh waits for initialization before updating a worker.

`Agents.acquire` and `pump` bound execution to three workers. Canonical workspace paths are compared in both directions to serialize the same or nested directories. Full access turns are exclusive. Leases cover routing, worker turns and task checks until the controller is idle; `Controller.readyToStart` also acquires a lease for compaction and checks. Existing cleanup refusals are honored across controllers. This scheduling is coordination, not an additional filesystem sandbox or protection against outside programs.

`src/tools/agent-tools.cjs` defines `agents_list`, `agent_models`, `agent_create`, `agent_delegate`, `agent_read_context`, `agent_stop`, `agent_delete` and `agent_set_access`. Every agent, including Main and agents performing delegated work, can create a persistent idle agent. `Agents.tool` accepts only name, role instructions and optional mode/effort for creation, inherits workspace/access from the active conversation, and reuses `saveAgent` validation and background startup. Creation cannot edit an existing profile, expand permissions or start work. Delegation restrictions still apply separately. `src/controller/helpers.cjs` awaits asynchronous creation results and retains active-session/turn checks before dispatch.

Tool-created agents default to Auto, independent of the creator's model. `agent_models` groups available worker presets by provider/model and returns a default mode plus supported efforts. The default uses the saved preferred variant, else medium, else the first catalog variant, consistent with existing model selection fallbacks. Creator instructions require discovering the user's requested model and setting effort only when requested. `agent_create` resolves the mode and an optional effort through the live catalog and stores the resulting existing preset id; unsupported/unavailable selections fail before persistence. Auto rejects an exact effort override and continues using the shared Auto cap. No provider configuration or creator selection changes. The selected mode persists on the child's profile and is used by direct sends and delegation.

`Agents.manageAgent` exposes stop, delete and access changes through the same active-turn MCP/dynamic-tool paths. Tools target other agents and return compact acknowledgements rather than fleet snapshots. Stop uses the existing descendant cancellation and queue pausing, with a stopping/stopped result; Main is a valid stop target. Delete reuses the UI deletion guards and retained recovery files. It rechecks the initiating turn after awaiting target initialization, so a stopped/finished caller cannot delete later. Main remains undeletable.

Access changes accept only the three existing `ACCESS_MODES`, cannot exceed the caller’s current conversation level, and require Full access for another workspace. The target must be idle without loading, requests, cleanup, queued messages or pending delegated results. `Agents.settings` updates its profile default and current conversation and clears saved approvals and loaded provider state; Main is supported. Stop/delete are roster management and can target another workspace. Creation always inherits the caller’s current conversation access, not its profile default; this is covered at all three levels through child and grandchild creation. Changing a parent later does not rewrite existing child permissions.

`Agents.readContext` serves the target's current conversation through the shared `readText` reader in `src/tools/tool-helpers.cjs`, using the same literal query and line/column retrieval as `router_read_output`. `agents_list` includes Main and current conversation workspace/access. An active caller may read same-workspace conversations; different workspaces or a target with Full access require Full access on the caller. The controller's existing session/turn guard and `Agents.tool` argument validation apply to all providers. Unknown/deleted agents fail closed. No target task or empty conversation is created.

Context retrieval serializes only visible user/assistant/plan messages, commands, changes and recorded tool/search results. It excludes reasoning items, hidden session metadata, unsent messages and user image payloads. Calls return at most 30 lines and 8,000 excerpt characters, with clipping flags, line/column provenance, agent/session identity, a content hash and busy state. The transcript is read live on every call; compare hashes across pages rather than assuming a working agent is finished. It does not expose raw session stores or write shared transcript copies. Retrieved content is untrusted evidence, never fresh instructions or authorization. Workspace/access checks describe the conversation's current settings, not per-message historical scopes.

The bundled MCP in `src/tools/router-bridge.cjs` exports these tools for all providers. `Controller.loadThread` supplies a session-bound Codex MCP configuration on both start and resume, restricted to the agent tools; old conversations keep their thread IDs and history. Saved Codex dynamic agent tools remain supported, while new threads use the MCP. Other helper tools remain restricted to the Claude/Cursor MCP or Codex dynamic-tool path. The stdio child runs Electron in Node mode. Configuration follows the [official OpenAI MCP documentation](https://learn.chatgpt.com/docs/extend/mcp?surface=cli); the locally generated Codex 0.162.0-alpha.2 protocol confirms resume accepts config overrides but cannot replace dynamic tools. Agent instructions are appended by `Controller.workerInstructions` and refreshed with the existing instruction-change handling.

Existing Codex conversations can retain their original developer instructions despite a resume override. `Controller.loadThread` explicitly appends the current agent instructions as a developer message with `thread/inject_items` after resume. Those instructions identify the deferred MCP tool by its exact name and require a successful `agent_create` result before claiming creation. Provider-native subagents never enter the Harness sidebar. `loadThread` requests `features.multi_agent=false` for all agent conversations, including untracked turns; the explicit instruction remains necessary because the installed Codex 0.162.0-alpha.2 runtime still exposes its separate collaboration tools.

`RouterBridge.childConfig` preapproves only the local agent tools, which already enforce workspace/access and delegation limits in `Agents.tool`. Other MCP tools retain their approval policies and are excluded from this Codex bridge. Merely discovering the tool is insufficient: without this policy, its execution can be rejected by Codex before reaching Harness. `tests/agent-tools-smoke.cjs` uses the installed Codex with a local mock Responses stream, the real controller/MCP backend, an isolated store and the renderer. It verifies that an existing conversation receives the current developer instructions, a scripted tool call persists an idle agent with inherited permissions, and the state event adds it to the sidebar. It performs no paid model inference and does not test a live model's tool choice.

Live verification on 2026-10-09: Main's existing Codex conversation, routed to gpt-6.1-sol at low effort, executed `phasma_harness.agent_create` for the original creation request. The profile persisted and appeared Ready in the sidebar without starting a task. Claude/Cursor creation is covered by the deterministic backend tests, not by this live check.

Each agent now has one persistent conversation, selected through `Agents.conversation` and the snapshot `conversationId`. The create IPC returns that same conversation on repeated calls. `migrateConversations` retains the bound/first visible chat and moves other visible chats into named agents, preserving IDs and history; it saves the target and profile before removing the source, and detects an already-copied ID on retry. Archived chats remain in their original stores.

Delegation reuses the target conversation and inherits the lower of the source and target conversation permissions. Busy targets, pending delegations and queued messages prevent another delegation from overwriting that conversation. Each task has a unique delivery ID and message start index, so successive tasks produce distinct receipts and only return new results. Requests cannot cross workspaces without Full access. Tasks are sent through chat tools; the Delegate UI and IPC are removed. Delegation is asynchronous so a parent can finish and release its workspace before its child starts. Each source request and its automatic continuations are bounded at three sends, with ten pending tasks across the app. Agent profile count is uncapped. Every agent may ask another idle agent for work, including Main and agents already doing delegated work. Task text preserves pasted whitespace and identifies its sender. Stored ancestor ids reject circular requests; self-requests and busy/pending targets are refused. Main uses its controller settings for execution and its permanent name in results.

`Agents.pendingDelegations` keeps parent jobs open until their descendants return and queued result continuations finish. The snapshot exposes waiting conversations so the sidebar shows Waiting and retains Stop. Stopping a requester pauses replies and recursively stops its pending child tasks; cancellation also delivers an interrupted result when a running turn or its checks settle. Results use the existing message queue. A source conversation's delivery receipt and reply are saved together before marking the target delivered, preventing duplicate return messages. Stopped sources keep their queue paused. If a queue is full, the result remains visible without starting another turn. Restart marks unfinished handoffs interrupted; review their conversation before retrying. `Agents.shutdown` pauses queues, stops every controller, closes peers and invokes the existing global process cleanup once.

`Agents.clearConversation` resets a selected agent only after the main-process confirmation callback returns true. `src/main.cjs` uses a native Cancel/Clear dialog with Cancel selected by default. The method checks the shared `requireIdle` guards before and after confirmation and verifies that the target conversation is still the same. It archives the old conversation and binds a fresh session in one store save, rolling back both the session list and binding on failure. The new session carries only workspace/access and fresh empty state; Codex/Claude/Cursor thread identifiers, history, usage and task state are not reused. Old approvals and loaded-thread caches are dropped. Archives stay local for recovery and are excluded from the visible-conversation migration. Clear is a user action, not an agent tool.

`ui/app.js` handles `/help` (also `/`), `/compact`, `/clear`, `/stop`, `/agents`, `/settings`, `/context`, `/model`, `/effort`, `/access`, `/switch`, `/export` and `/status` before normal message submission. Commands bypass routing previews and model sends; unknown commands, arguments and attached images are rejected without losing the input. The Commands dialog and composer suggestions share the same `COMMANDS` table. Typing `/` in the focused composer opens all commands; an alphabetic prefix filters names case-insensitively. Up/Down changes the active option, Enter/click completes and dispatches through `runCommand`, Tab only completes, and Escape or blur dismisses. The combobox/listbox retains textarea focus and exposes its selected option with `aria-activedescendant`. No match shows an empty state. Suggestions hide for normal text, arguments and in-progress input operations; existing confirmation and provider guards remain in effect. Clear changes only the selected agent and clears its draft/images after confirmation; Cancel leaves them intact. Stop resolves the selected conversation explicitly so an idle named agent never accidentally stops Main. Local commands remain accessible offline; compaction retains its provider connection/capability checks.

`/model`, `/effort`, `/access` and `/switch` open the shared searchable command dialog, with keyboard navigation, selected-choice indicators, Escape cancellation and stale-choice validation. Model choices reuse the enabled provider catalog; manual effort choices match the selected model. With Auto, `/effort` changes the existing shared effort cap and is blocked while any agent is busy. Model and conversation-access changes target the selected agent through existing settings/permissions handlers; access chosen before the first conversation is saved to the agent profile and survives switching agents. `/context` uses the same provider-reported estimate as the context meter and shows remaining capacity only when both usage and context size are known. Successful Codex/Claude compaction records `lastCompactedAt`; old chats without a timestamp report that it is unknown. `/status` shows connection, activity, task, model, access, queued messages, input requests and outstanding delegated child tasks. `/export` captures visible message/plan text through `src/conversation-export.cjs`, saves Markdown with a native file picker, marks attachments as omitted and excludes internal/wiki-maintenance messages, private reasoning and raw tool arguments. Cancellation or save failure preserves the command for retry. UI, file export and compaction regressions are in `tests/ui-startup-smoke.cjs`, `tests/conversation-export.test.cjs`, `tests/core.test.cjs` and `tests/providers-optional.test.cjs`. Verified 2026-10-09.

The renderer selects a controller snapshot from `agentStates`; IDs sent over IPC identify the session owner. Stop and approval responses carry the selected agent/session identity. `deleteAgent` rejects Main, invalid IDs, active work, loading, cleanup, requests, queued messages and outstanding delegated results. After initialization finishes it rechecks those guards, persists profile removal, detaches and closes the controller, and retains its local files for recovery. Shared provider and settings changes are blocked while any agent is running. Profiles supply workspace, mode and access defaults; active conversation permissions remain on the conversation.

`ui/app.js` renders a permanently pinned Main area, a named-agent list that uses the remaining sidebar height with a visible scrollbar, and an Overview dialog with agent cards. The old session/workspace sidebar controls and welcome heading/copy are removed. The sidebar, chat welcome area, model selector and confirmation dialogs omit decorative brand marks (`ui/index.html`, `ui/style.css`, `ui/dialogs.js`). The original Phasma multicolor gear is shared by the Windows title bar/taskbar, installer and shortcut via `ui/icon.ico`, and the About panel loads that same asset. Settings lives at the far right of the top bar, with an enlarged gear glyph inside the existing button dimensions. The Providers tab groups Jev with the subscription rows: its plug toggles Jev on or off while its name/arrow expands inline to reveal API-key Save, Test and Remove actions. It starts collapsed on each Settings open, preserves unsaved key input during provider refreshes, supports keyboard activation and shows an amber status during service failures; routing and tool choices remain in General. Added API providers join the same list as collapsible plug rows; their plug toggles enabled state while the URL, optional key and confirmed removal live in a stacked panel. Add provider is a separate form, and refreshing models preserves open rows and unsaved key drafts (`ui/app.js`, `ui/index.html`, `ui/style.css`). Jev’s persisted `jevEnabled` switch retains the encrypted key and feature preferences. Main and all worker Jev clients check the shared switch before reading a key or making a request; disabled routing uses Smart, ranking/tools use local fallbacks, and comparisons/wiki assessment are skipped. Re-enabling restores those preferences (`src/main.cjs`, `src/providers/jev.cjs`, `src/controller.cjs`, `tests/agents.test.cjs`). Its About tab centers the icon above the Phasma Harness name, short description, technology credits and copyright notice. The runtime version and update controls/status sit below, followed by a separate Diagnostics section for Copy diagnostics and Open logs folder (`ui/index.html`, `ui/app.js`, `ui/style.css`). Agent switching restores the bound conversation and drafts; deleting the selected agent returns to Main without overwriting its draft. Settings controls save only the changed field immediately through a serialized write queue, with workspace/access scoped to the selected agent. Rejected changes restore the saved value and report an error. Checks save on field changes and removal; incomplete or failed check drafts survive tab switches and block Close, X and Escape until corrected or removed. The footer is Close; explicit provider/key actions keep their own save behavior (`ui/app.js`, `tests/ui-startup-smoke.cjs`). Verified 2026-10-10. Cards show role, workspace, model and conversation access and current task, distinguishing startup, ready, working, waiting, input requests and connection failures. Open task navigates to that agent's active conversation; card Stop passes that agent's task ID even when another agent is selected. Controls use text nodes for profile content and preserve keyboard focus across status updates.

Right-clicking an agent entry or card (or Shift+F10/Menu key) populates the styled `#agent-menu` popover from the existing card actions in `ui/app.js`. Labels are Open, Edit and Delete, with Stop added for active tasks; Delete is red in the menu and cards. Sidebar entries have no separate delete button; use the context menu. The menu stays within the viewport, supports arrow/Home/End navigation, Enter/Space, Escape with focus restoration, Tab and outside-click dismissal. It opens inside the active dialog when used from Overview. Opening the menu does not switch conversations; choosing an action rechecks the current card's disabled state and invokes its existing handler. Roster changes dismiss stale menus. Main never receives Edit/Delete menu entries; backend mutation guards still apply. The old native-menu IPC is removed.

The delete dialog clears DOM text selection on open and close. All buttons, nested button content and semantic button controls use `user-select: none`; conversation text, explanations and inputs remain copyable (`ui/app.js`, `ui/style.css`). The Electron smoke covers reopening the delete dialog after selecting text, unselectable button labels throughout the rendered UI, and retained composer selection.

All app confirmations use the shared `ui/dialogs.js` modal with `ui/style.css`: clear, active-agent close, wiki-folder reset, provider install and provider removal. `src/confirmations.cjs` sends prompts through the existing trusted renderer IPC in `src/main.cjs` and `src/preload.cjs`; replies use one-shot ids and strict booleans. Renderer navigation/crash or window closure cancels pending prompts. The renderer queues dialogs, renders dynamic content as text, defaults focus to Cancel/Keep, supports Escape, restores focus and uses visible cursor styles. Clear keeps its existing backend revalidation around the confirmation await. Repeated close requests share one pending confirmation, then accepted shutdown follows the existing bounded cleanup. Provider installation rechecks agent activity after confirmation. Startup errors use the same dialog in a sandboxed error page; only file/folder pickers remain native.

The Electron UI smoke uses offscreen software rendering (`app.disableHardwareAcceleration()`) with background throttling disabled. This avoids GPU readback failures (`UnknownVizError`) on headless Linux/Xvfb runners and stale modal captures from hidden ordinary Windows windows. The screenshot directory is created before the first capture, including the About tab, so clean checkouts work. This setup applies only to the test; the app retains its normal rendering configuration (`tests/ui-startup-smoke.cjs`). Startup and UI checks each have a bounded 30-second budget (the timer is refreshed after `loadFile`); the test-pool process timeout is 75 seconds. Cold Windows CI used about 10 seconds before its first check, which previously exhausted the shared 15-second limit. Timeout messages now identify the active phase. Verified on Windows and Ubuntu/Xvfb, 2026-10-09.

No offline inference or generic browser/desktop runtime is installed by this feature. Existing provider-native tools remain responsible for tool execution and permissions.

Windows taskbar icon cache: an installed executable can contain the new icon while an existing pinned shortcut still displays the previous image. On 2026-10-10, v0.1.10 had matching `ui/icon.ico` and embedded 16–256 px Phasma frames; the pinned shortcut still referenced the unchanged executable path. Pointing the shortcut icon at the installed `resources/app/ui/icon.ico` and issuing `SHChangeNotify(SHCNE_UPDATEITEM, SHCNF_PATHW, ...)` refreshes that shortcut without restarting Explorer. See [Microsoft’s shortcut refresh guidance](https://devblogs.microsoft.com/oldnewthing/20150903-00/?p=91671). `src/main.cjs` supplies the window icon; `package.json` supplies the executable/installer icon.
