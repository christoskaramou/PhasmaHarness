# Local agents

Verified against live source: 2026-10-09.

`src/agents.cjs` coordinates the existing `Controller` instances. Hub retains `sessions.json`; each named agent uses `agents/<uuid>/sessions.json` under the same application data directory. The primary store holds agent profiles. Each controller owns its provider processes, routing state, approvals, tool bridge, turn queue and cleanup state. `src/main.cjs` creates separate API proxy instances too: the proxy's model effort map must not be shared across concurrent agents.

`Agents.saveAgent` persists and returns the profile without awaiting `initializeController`. Startup runs in the background with errors retained in the controller snapshot. `Controller.initialize(shared)` reuses the primary Claude/Cursor status and models after primary discovery completes instead of repeating their auth/model-discovery subprocesses; each agent still connects its own Codex app-server. Closing guards prevent a pending configuration or bridge startup from launching another worker after shutdown begins. Shared provider refresh waits for initialization before updating a worker.

Verified 2026-10-10: agents execute independently, with no global worker-slot cap, workspace lease or Full-access exclusivity. `Agents.acquire` retains closing, Stop and cross-controller cleanup checks but no longer queues by another agent's workspace/access; `Controller.readyToStart` applies the same cleanup guards before execution. `Agents.pump` handles delegation and result delivery only. Each controller still permits one active turn and queues its own messages. Same-directory and nested-directory workers keep their original access and can start together. Files remain shared, so concurrent edits can conflict; provider limits and local-server inference/model-management locks remain in effect. `tests/agents.test.cjs` verifies five simultaneous Full-access workers, separate provider conversations/queues, nested workspaces, changing access without a global lock, and targeted Stop. `tests/coordinator.test.cjs` verifies four Full-access batch reviewers start concurrently with the exact requested model and effort.

`src/tools/agent-tools.cjs` defines `agents_list`, `agent_models`, `agent_create`, `agent_delegate`, `agent_read_context`, `agent_stop`, `agent_delete` and `agent_set_access`. Every agent, including Hub and agents performing delegated work, can create a persistent idle agent. `Agents.tool` accepts only name, role instructions and optional mode/effort for creation, inherits workspace/access from the active conversation, and reuses `saveAgent` validation and background startup. Creation cannot edit an existing profile, expand permissions or start work. Delegation restrictions still apply separately. `src/controller/helpers.cjs` awaits asynchronous creation results and retains active-session/turn checks before dispatch.

Tool-created agents default to Auto, independent of the creator's model. `agent_models` groups available worker presets by provider/model and returns a default mode plus supported efforts. The default uses the saved preferred variant, else medium, else the first catalog variant, consistent with existing model selection fallbacks. Creator instructions require discovering the user's requested model and setting effort only when requested. `agent_create` resolves the mode and an optional effort through the live catalog and stores the resulting existing preset id; unsupported/unavailable selections fail before persistence. Auto rejects an exact effort override and continues using the shared Auto cap. No provider configuration or creator selection changes. The selected mode persists on the child's profile and is used by direct sends and delegation.

`Agents.manageAgent` exposes stop, delete and access changes through the same active-turn MCP/dynamic-tool paths. Tools target other agents and return compact acknowledgements rather than fleet snapshots. Stop uses the existing descendant cancellation and queue pausing, with a stopping/stopped result; Hub is a valid stop target. Delete reuses the UI deletion guards and retained recovery files. It rechecks the initiating turn after awaiting target initialization, so a stopped/finished caller cannot delete later. Hub remains undeletable.

Access changes accept only the three existing `ACCESS_MODES`, cannot exceed the caller’s current conversation level, and require Full access for another workspace. The target must be idle without loading, requests, cleanup, queued messages or pending delegated results. `Agents.settings` updates its profile default and current conversation and clears saved approvals and loaded provider state; Hub is supported. Stop/delete are roster management and can target another workspace. Creation always inherits the caller’s current conversation access, not its profile default; this is covered at all three levels through child and grandchild creation. Changing a parent later does not rewrite existing child permissions.

`Agents.readContext` serves the target's current conversation through the shared `readText` reader in `src/tools/tool-helpers.cjs`, using the same literal query and line/column retrieval as `router_read_output`. `agents_list` includes Hub and current conversation workspace/access. An active caller may read same-workspace conversations; different workspaces or a target with Full access require Full access on the caller. The controller's existing session/turn guard and `Agents.tool` argument validation apply to all providers. Unknown/deleted agents fail closed. No target task or empty conversation is created.

Context retrieval serializes only visible user/assistant/plan messages, commands, changes and recorded tool/search results. It excludes reasoning items, hidden session metadata, unsent messages and user image payloads. Calls return at most 30 lines and 8,000 excerpt characters, with clipping flags, line/column provenance, agent/session identity, a content hash and busy state. The transcript is read live on every call; compare hashes across pages rather than assuming a working agent is finished. It does not expose raw session stores or write shared transcript copies. Retrieved content is untrusted evidence, never fresh instructions or authorization. Workspace/access checks describe the conversation's current settings, not per-message historical scopes.

Provider-native subagents never enter the Harness sidebar. `loadThread` requests `features.multi_agent=false` for all agent conversations, including untracked turns; the explicit instruction remains necessary because the installed Codex 0.162.0-alpha.2 runtime still exposes its separate collaboration tools.

Archived chats remain in their original stores.

Delegation reuses the target conversation and inherits the lower of the source and target conversation permissions. Busy targets, pending delegations and queued messages prevent another delegation from overwriting that conversation. Each task has a unique delivery ID and message start index, so successive tasks produce distinct receipts and only return new results. Requests cannot cross workspaces without Full access. Tasks are sent through chat tools; the Delegate UI and IPC are removed. Delegation is asynchronous so a parent can finish and release its workspace before its child starts. Each source request and its automatic continuations are bounded at three sends, with ten pending tasks across the app. Agent profile count is uncapped. Every agent may ask another idle agent for work, including Hub and agents already doing delegated work. Task text preserves pasted whitespace and identifies its sender. Stored ancestor ids reject circular requests; self-requests and busy/pending targets are refused. Hub uses its controller settings for execution and its permanent name in results.

`Agents.pendingDelegations` keeps parent jobs open until their descendants return and queued result continuations finish. The snapshot exposes waiting conversations so the sidebar shows Waiting and retains Stop. Stopping a requester pauses replies and recursively stops its pending child tasks; cancellation also delivers an interrupted result when a running turn or its checks settle. Results use the existing message queue. A source conversation's delivery receipt and reply are saved together before marking the target delivered, preventing duplicate return messages. Stopped sources keep their queue paused. If a queue is full, the result remains visible without starting another turn. Restart marks unfinished handoffs interrupted; review their conversation before retrying. `Agents.shutdown` pauses queues, stops every controller, closes peers and invokes the existing global process cleanup once.

Old approvals and loaded-thread caches are dropped. Archives stay local for recovery and are excluded from the visible-conversation migration. Clear is a user action, not an agent tool.

## Hub coordination

Verified 2026-10-10: `agent_work.count` creates one to ten independent workers for an explicitly requested batch, preserving the same task, requested model/effort, workspace, images and access (`src/controller/coordinator.cjs`). Counts and queue capacity are checked before creation; partial failures report the actual number dispatched. `Agents.checkDelegationCapacity` shares the ten-task Hub budget and global pending limit across single and batch calls; named agents retain their three-task limit. Each ready batch worker executes independently without a workspace lock or global worker-slot cap (`src/agents.cjs`).

Each batch assignment carries its group id, count and index alongside the original request. Workers are told to perform one full instance, leaving peer creation to Hub. Completion checks assess that assignment; result-message metadata persists each verified outcome in visible history, with bounded follow-ups replacing only the relevant worker result. Hub reports progress until every dispatched member returns, then supplies all reports to the final synthesis. Cancellation, exhausted budgets and failed/undispatched members prevent a full-completion claim. The original message stores dispatch progress so partial creation failures cannot leave Hub waiting for nonexistent workers. `tests/coordinator.test.cjs` covers four-worker dispatch at an exact model/effort, persistence, aggregation, capacity rejection, partial failures, cancellation and bounded continuations (pool `coordinator`). These tests use isolated provider fixtures, not paid model calls.

## Local model memory and context

Verified 2026-10-10. `src/providers/local-models.cjs` discovers model-management APIs at the configured provider endpoint (preserving reverse-proxy prefixes and authentication). LM Studio supports load/unload and context sizing; Ollama uses a Harness-named preset derived from the downloaded model with `num_ctx` set, because OpenAI-compatible requests do not retain a one-off native context override. These small preset definitions reuse weights; the original model is unchanged. llama.cpp router mode supports load/unload, but context size is server configuration. Unsupported endpoints and hosted providers keep their existing inference path. No model downloads are started.

Workers and the routing classifier prepare local models before inference. The default is 32,768 tokens, capped by model limits and preserving larger loaded contexts. Both local inference paths share `Providers.modelRequest`, which rechecks after eviction, estimates request room (excluding image data), and can grow adjustable contexts up to 262,144 tokens or the model maximum. An HTTP context rejection reporting the required tokens gets one larger-context retry before any output is forwarded. This estimate is not a tokenizer; streaming errors, unavailable memory, server-fixed context and intrinsically oversized prompts can still require a smaller request or different model. Codex receives the verified active window and a 75% auto-compaction threshold; existing threads resume with updated configuration without clearing history (`src/controller.cjs`, `src/routing/smart-router.cjs`, `src/providers/providers.cjs`).

Structured calls from Hub (chat, coordination and compaction) and Smart routing use `Providers.structured` for detected local servers. They send system instructions, a bounded user prompt, optional images and an explicit JSON schema to `/v1/chat/completions`, without execution tools. LM Studio/Ollama receive `response_format.json_schema`; llama.cpp receives its `response_format.schema` form. The local Responses endpoint is not relied on for schema enforcement. JSON parsing and caller validation still fail closed: plain text, incomplete output and invalid Hub actions cannot become actions. The existing provider lock covers loading and the complete response, including cancellation. Unknown/hosted providers and subscription backends retain their existing paths.
